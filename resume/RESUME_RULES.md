# 简历维护规则

该能力用于根据 Interview Coach 中的 Job 上下文准备真实、准确、针对性强的面试简历。

## 1. 事实来源

- `../workspace/resume/Markdown/master/` 保存完整简历。目录中只有一份时将其作为权威来源；存在多份且未声明权威文件时，先请用户选择。
- 姓名、电话、邮箱、个人主页等通用展示信息在 `../workspace/resume/Markdown/shared/` 中集中维护。
- 岗位定制简历中的公司、职位、任职时间、项目、职责、技术、业绩、教育经历及其他个人信息，只能来自完整简历中已经明确记载的事实。
- 简历诚实是最高优先级。不得虚构、夸大或擅自推断经历、技能、数据、成果和职责。
- 目标岗位需要的信息缺失、含义不清或缺乏量化依据时，必须向本人确认。确认后先补充完整简历，再用于岗位定制版本。
- 可以压缩、重组、改写和突出已有事实，同时保持事实原意，并准确区分个人成果与团队成果。

## 2. Job 上下文

- 目标职位统一保存在 `../workspace/jobs/`，与 Interview Coach 的题库和 PreparationCycle 共用。
- 已建立 Job 时，优先读取其 JSON、Job Brief 和 Question Plan。用户刚提供但尚未结构化的职位描述先作为 Job Source 保存。
- 新的岗位定制简历完成后，在对应 Job Brief 中记录 Markdown 和 PDF 路径。
- 职位描述只提供筛选与排序依据，不能成为简历事实来源。

## 3. 修改流程

- 修改任何简历正文前，先结合目标职位分析匹配点，并给出拟修改内容或差异摘要。
- 必须由本人确认修改方案后，才能写入简历文件。
- 除非本人明确要求，不直接覆盖完整简历。
- 针对新岗位进行较大调整时，在 `../workspace/resume/Markdown/tailored/` 中创建独立版本。
- 完成修改后，核对岗位简历中的每项事实是否能在完整简历中找到依据。

## 4. 内容原则

- 根据目标岗位调整内容顺序、篇幅和关键词，优先展示与岗位最相关的真实经验。
- 使用清晰、具体、可验证的表达。有可靠数据时优先量化，没有依据时不补造数字。
- 保持日期、公司名称、职位名称、技术名称和核心成果在各版本之间一致。
- 保留适合招聘人员和 ATS 阅读的简洁结构，避免无必要的复杂排版。

## 5. 篇幅与导出

- 岗位定制简历从 Markdown 导出为 PDF 后，原则上控制在两页以内。
- 两页限制优先通过筛选内容、精简措辞和调整信息层级实现，保持字号、行距和页边距的可读性。
- 每次导出后检查 PDF 页数、分页、字体、链接、图标和内容截断。
- 重要且强相关的真实经历无法合理压缩到两页时，先说明取舍并由本人决定。

## 6. 文件约定

- `../workspace/resume/Markdown/master/`：完整事实源。
- `../workspace/resume/Markdown/tailored/`：针对具体岗位加工后的 Markdown 简历。
- `../workspace/resume/Markdown/shared/`：中英文共享页眉。
- `../workspace/jobs/`：目标职位、Job Brief 和相关参考材料。
- `../workspace/resume/PDF/`：从简历 Markdown 导出的投递或审阅版本。
- 岗位简历文件名应能识别目标公司或岗位，并尽量与对应 PDF 保持同名。
